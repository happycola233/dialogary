# chatlog-md 格式规范 v1

一种用于**长期保存 AI 对话日记**的纯 Markdown 格式。目标读者：未来的你（人类阅读）、你写的解析器/网页查看器（程序解析）。

约定文件扩展名：`*.chat.md`（仍是 Markdown，Typora / VS Code / GitHub 都能直接打开）。

---

## 1. 设计目标与原则

1. **纯文本、纯 Markdown**：不依赖内联 HTML 样式做结构。几十年后即使没有任何配套软件，用记事本也能读。
2. **人读优先，机器可靠**：解析器只识别少数几种**行首哨兵**（见 §3），其余一切都是正文原样透传。因此正文里可以出现任意内容——H1 标题、`---` 分隔线、代码块、HTML——都不会破坏结构。
3. **一切元数据可缺省**：没有时间、没有模型名的消息都合法；有就记录，没有就省略。
4. **单一事实来源**：同一信息只写一次。不搞"可见文本 + 隐藏注释各存一份"的双写（双写必然腐烂）。
5. **可演进**：预留统一扩展点 `<!-- @meta ... -->`，未来加字段（平台、账号、标签、收藏……）不破坏旧解析器。

推荐的使用管线：

```
聊天记录.chat.md  ←(源文件，人类手工维护)
      │  解析器
      ▼
   JSON / 内存对象  →  网页查看器（大纲、只看用户消息、按日期跳转、折叠思考块……）
```

---

## 2. 完整示例

```markdown
---
format: chatlog-md/1
title: 聊天记录
timezone: Asia/Shanghai
---

# @2025-03-28 · 周五
<!-- @meta platform=ChatGPT -->

## 🧑‍💻 @user · 2025-03-28 23:04:06

今天好累，求个抱抱 qwq

## 🤖 @ai · 2025-03-28 23:04:19 · gpt-5-1-thinking

> 🤔 已思考 40s
>
> **理解用户的情绪**
> 用户表达了疲惫，需要安慰和鼓励……

**抱抱你！！** 真的辛苦了……

# 正文里出现 H1 也没关系，它不是哨兵，解析器不理会

## 🧑‍💻 @user

🖼️ 1000078148.jpg
🖼️ [1000078140.jpg](assets/1000078140.jpg)

嘿嘿，看图！（这条消息没有时间戳，也合法；时间上默认继承上文）

## 🤖 @ai

（同角色连续出现也合法——每条消息独立一个消息头，不假定一问一答）
```

## 3. 词法：哨兵行（解析器唯一需要识别的东西）

解析器逐行扫描，**只有下列行首模式具有结构含义**，其余所有行一律是当前消息的正文：

| 行首模式 | 含义 | 详见 |
|---|---|---|
| `---`（仅文件最开头） | 文档头 front matter | §4 |
| `# ` … `@YYYY-MM-DD` | 日期节（session） | §5 |
| `## ` … `@user` / `@ai` / `@system` | 消息头 | §6 |
| `> 🤔`（且位于消息正文的第一个块） | 思考块开始 | §7 |
| `🖼️ ` / `📄 ` | 附件行 | §8 |
| `<!-- @meta ` | 扩展元数据（附着于上一个哨兵） | §9 |

**关键点**：`#`/`##` 本身不是哨兵，`@角色`/`@日期` 才是。正文中的普通标题（`# 标题`、`## 标题`）因为不含 `@user`/`@ai`/`@日期` 记号，不会被误认。这就是"正文可以包含 H1"的保证来源。极端撞车情况见 §10 转义规则。

---

## 4. 文档头（front matter）

文件**第一行**起的 YAML front matter，`---` 包围。仅出现一次。

```yaml
---
format: chatlog-md/1        # 必填。格式名/主版本，解析器据此判断兼容性
title: 聊天记录              # 可选
timezone: Asia/Shanghai     # 可选但强烈建议。文中所有时间戳都按此时区理解
---
```

未识别的键一律保留、忽略（向前兼容）。

---

## 5. 日期节（session）

语法：

```
# @YYYY-MM-DD
# @YYYY-MM-DD · <自由标题>
```

- 一级标题 + `@日期` 记号。`·` 后的标题任意（星期、主题、"深夜倾诉"……），解析器原样存储。
- 作用：① 给日记提供天然的按日大纲；② 为**没有时间戳的消息**提供日期上下文（见 §11）。
- 正则：`^#\s+@(\d{4}-\d{2}-\d{2})(?:\s*·\s*(.+))?\s*$`
- 日期节可以不存在（整个文件没有 `# @` 也合法，此时全部消息属于一个隐式 session）。

---

## 6. 消息头

语法：

```
## <装饰> @<角色>[ · <字段>][ · <字段>]…
```

- **角色**：`user` | `ai` | `system`（保留，可扩展）。解析器锚定 `@角色` 记号；`@` 之前的内容（emoji、显示名之类）是**纯装饰**，解析器忽略。
  - 推荐装饰：用户 `## 🧑‍💻 @user`，AI `## 🤖 @ai`。
- **字段**：`@角色` 之后用 ` · `（U+00B7 中点）分隔零个或多个字段，**按形状识别、不按位置**：
  - 长得像时间戳的 → 时间（见下）；
  - 其余 → 模型名（仅对 `@ai` 有意义，如 `gpt-5-1-thinking`）。
  - 每类字段至多一个；都可省略。
- **时间戳三种精度**，本地时间（时区见文档头）：

  | 精度 | 写法 | 正则 |
  |---|---|---|
  | 日 | `2025-02-17` | `\d{4}-\d{2}-\d{2}` |
  | 分 | `2025-02-17 21:04` | `… \d{2}:\d{2}` |
  | 秒 | `2025-02-17 21:04:06` | `… \d{2}:\d{2}:\d{2}` |

- 消息头正则（供参考）：

  ```
  ^##\s+(?:[^@\r\n]*?)@(user|ai|system)((?:\s*·\s*[^·\r\n]+)*)\s*$
  ```

- **消息体**：消息头之后直到下一个消息头 / 日期节 / 文件结尾的所有内容（去掉首尾空行），100% 原样保存。
- **同角色连续出现天然合法**：每条消息独立一个 `##` 头，格式不假定一问一答。

---

## 7. 思考块（AI 推理摘要）

出现在 AI 消息正文的**第一个块**，用 Markdown 引用块表达（任何查看器里都能正常渲染；自定义查看器可将其渲染为可折叠区域）：

```markdown
> 🤔 已思考 1m 24s
>
> **回应用户提出的请求**
> 用户已经贴出了之前的对话记录……
>
> **回应情感需求**
> 我会回应用户的需求……
```

- **标记行**：`> 🤔 <自由文本>`。自由文本通常是"已思考 1m 24s"这类时长描述，解析器原样存储（也可进一步用 `(\d+)m`、`(\d+)s` 提取秒数，属于查看器层面的事）。
- **范围**：标记行开始，到引用块结束（第一个不以 `>` 开头的非空行）为止。
- 思考块内部的 `**加粗标题** + 段落` 就是"思考摘要条目"，查看器可按空引用行（`>`）分段展示。
- 只有位于消息正文**开头**的 `> 🤔` 引用块才是思考块；正文中间的引用块（哪怕以 🤔 开头）一律视为普通正文。

## 8. 附件行

表示"这条消息附带了一个文件"（通常是用户上传的图片）。一行一个附件，可连续多行：

```markdown
🖼️ 1000078148.jpg
🖼️ [1000078140.jpg](assets/1000078140.jpg)
📄 成绩单.pdf
```

两种写法：

| 写法 | 含义 |
|---|---|
| `🖼️ <显示名>` | 只知道文件名，文件本体不在本地（无法或尚未保存） |
| `🖼️ [<显示名>](<相对路径或URL>)` | 文件已保存，查看器可直接加载渲染 |

- **哨兵**：行首 `🖼️ `（图片）或 `📄 `（其他文件），后跟显示名或标准 Markdown 链接。
- 正则：链接形 `^([🖼️📄])\s+\[([^\]]+)\]\((.*)\)\s*$`（路径贪婪到行尾右括号，兼容 `image(57).png` 这类含括号的文件名）；纯名形 `^([🖼️📄])\s+(\S.*?)\s*$`（先试链接形）。
- **归属**：附件属于所在消息，解析后进入该消息的 `attachments` 列表，不算正文。位置不限，但推荐放在消息体开头。
- 本地文件推荐统一放在与 `.chat.md` 同目录的 `assets/` 下，用相对路径引用。
- 需要记录额外信息（如图片宽高、来源）时，在附件行的**下一行**跟一个 `<!-- @meta ... -->`（见 §9），键值附着到该附件上：

  ```markdown
  🖼️ [1000078140.jpg](assets/1000078140.jpg)
  <!-- @meta w=4098 h=2481 -->
  ```

## 9. 扩展元数据 `<!-- @meta ... -->`

统一扩展点。紧跟在**日期节头**、**消息头**或**附件行**之后（可隔空行）的一行：

```markdown
# @2025-12-05 · 周五
<!-- @meta platform=ChatGPT account=main -->

## 🧑‍💻 @user · 2025-12-05 01:20:11
<!-- @meta starred=true tags=日记,考试 -->
```

- 语法：`<!-- @meta key=value key2=value2 -->`，value 含空格时用双引号。
- 解析器把键值对附着到上一个哨兵对象上；**未识别的键必须保留并忽略**。
- 这是加"平台、账号、标签、收藏、心情评分"等未来字段的地方，不需要升级格式版本。

---

## 10. 转义规则（极端撞车兜底）

若正文某行**恰好**匹配哨兵语法（例如一行以 `## @user` 开头的引用示例，或以 `🖼️ ` 开头的普通文字），在行首加反斜杠：

```markdown
\## @user 这行是正文，不是消息头
\🖼️ 这行也是正文，不是附件
```

解析器遇到 `\` 开头且去掉 `\` 后匹配哨兵语法的行，剥掉一个 `\` 后按正文处理。写入工具应自动检测并转义（实际语料中概率≈0，但规范必须封死这个口子）。

---

## 11. 时间与排序规则

1. 整个文件按时间**从早到晚单调不减**排列（这是文档级约定，lint 项，见 §13）。
2. 无时间戳的消息：时间上**继承上文**——即"不早于上一条已知时间，不晚于下一条已知时间"；其所属日期由所在日期节给出。
3. 不同精度比较时按前缀比较（`2025-02-17` 与 `2025-02-17 21:04` 不冲突）。

---

## 12. 解析器实现指引 + JSON 映射

单遍状态机即可，伪代码：

```
state = (front_matter, sessions[], cur_session, cur_msg)
for line in file:
    if 文件头未结束: 收集 YAML
    elif line 匹配 日期节:   收尾 cur_msg; 新建 session
    elif line 匹配 消息头:   收尾 cur_msg; 新建 message(role, time, model)
    elif line 匹配 @meta:    键值附着到最近的哨兵对象
    else:                    追加到 cur_msg.body_lines
后处理每条消息:
    去首尾空行
    若首块为 "> 🤔" 引用块 → 剥离为 thinking{label, text}
    扫描 "🖼️ "/"📄 " 行 → attachments[]
    行首 "\" 转义还原
```

建议的 JSON 输出结构：

```json
{
  "format": "chatlog-md/1",
  "meta": { "title": "聊天记录", "timezone": "Asia/Shanghai" },
  "sessions": [
    {
      "date": "2025-03-28",
      "title": "周五",
      "meta": {},
      "messages": [
        {
          "role": "ai",
          "time": "2025-03-28 23:04:19",
          "time_precision": "second",       // "day" | "minute" | "second" | null
          "model": "gpt-5-1-thinking",       // 可为 null
          "thinking": {                       // 可为 null
            "label": "已思考 40s",
            "text": "**理解用户的情绪**\n用户表达了……"
          },
          "attachments": [
            { "kind": "image", "name": "1000078148.jpg", "path": null, "meta": {} }
          ],
          "content": "**抱抱你！！** 真的辛苦了……",
          "meta": {}
        }
      ]
    }
  ]
}
```

消息的稳定 ID 不写进源文件（手工维护 ID 必烂），由解析器派生：`sha1(role + time + session内序号)` 或干脆用全局序号。

## 13. Lint 规则（解析器应告警的情况）

| 级别 | 规则 |
|---|---|
| error | 消息头出现未知角色 |
| error | 同一消息头出现两个时间戳形状的字段 |
| warn | 时间戳违反单调不减 |
| warn | 消息时间戳日期与所在日期节的日期不一致 |
| warn | `@ai` 之外的消息带模型字段 |
| warn | 正文行疑似未转义的哨兵（如 `^## @user`） |
| warn | 附件链接指向的本地文件不存在 |
| info | 空正文消息 |

---

## 14. 版本化

- 格式名/主版本写在 front matter 的 `format` 键：`chatlog-md/1`。
- 加新 `@meta` 键、新装饰、不改变现有哨兵语义 → 不升版本。
- 改变哨兵语法或语义 → 升 `chatlog-md/2`，并提供迁移工具。
